# Схема использования модели в бизнес-процессе проекта

## Диаграмма мониторинга

![Retraining FlowChart](docs\images\retraining.svg)

## 1: Триггер запуска переобучения
* Что происходит: Конвейер активируется при наступлении одного из трех независимых событий: по расписанию (раз в месяц), либо вручную при фиксации дрейфа данных, либо при накоплении более 50 новых подтвержденных инцидентов поломок в журнале ТОиР.
* Результат для следующего шага: Сигнал запуска пайплайна с параметрами временного окна для выгрузки данных.

## 2: Получение и подготовка новых данных
* Что происходит: Автоматические скрипты собирают свежие логи телеметрии и метки ремонтов из баз данных. На этом этапе формируются финальные признаки, обрабатываются пропуски датчиков, а выборка делится на обучающий и валидационный датасеты с сохранением временной последовательности.
* Результат для следующего шага: Подготовленные в рамках ETL-процесса обучающая и тестовая выборки в виде, оптимизированном для эффективной загрузки в CatBoost

## 3: Обучение новой версии модели
* Что происходит: Запускается обучение алгоритма градиентного бустинга CatBoostClassifier на обновленном датасете. В процессе обучения все ключевые параметры и итоговые метрики качества автоматически логируются в MLflow Tracking.
* Результат для следующего шага: Обученный артефакт модели CatBoost и зарегистрированные в MLflow метрики на тестовом срезе.

## 4: Проверка качества (Автоматический фильтр)
* Что происходит: Автоматический скрипт обращается к MLflow Tracking, извлекает метрики новой обученной модели и сравнивает их с метриками текущей работающей в продакшене модели на фиксированном контрольном датасете.
* Результат для следующего шага: Логический вердикт прошла или нет новая версия Quality Gate.

## 5: Принятие решения о возможности публикации
* Что происходит: Проверяется выполнение жестких бизнес-критериев: новая модель должна превосходить текущую по метрике Recall (чтобы не пропускать поломки) без критического падения Precision (чтобы не перегружать бригаду ложными вызовами).
* Результат для следующего шага: Автоматическое разветвление процесса: переход к регистрации и деплою при успехе, либо запуск протокола блокировки при неудаче.

## 6 (Успех): Регистрация новой версии модели
* Что происходит: Артефакт CatBoostClassifier автоматически сохраняется в MLflow Model Registry. Ей присваивается очередной порядковый номер версии и первоначальный статус кагндидата.
* Результат для следующего шага: Зарегистрированная модель в репозитории MLflow, готовая к развертыванию.

## 7 (Успех): Деплой модели
* Что происходит: На основе новой версии из MLflow Model Registry обновляется микросервис инференса. Развертывание в продакшене происходит плавно (например, с использованием канареечного релиза), переводя поток данных со станков на новую модель.
* Результат для следующего шага: Обновленная модель CatBoostClassifier успешно принимает данные в продакшене. Процесс завершен.

## 6а (Отказ): Действия при неуспешном прохождении проверок
* Что происходит: Если новая модель уступает текущей по качеству, процесс публикации блокируется. Новая версия CatBoost отклоняется и отправляется в архив для последующего анализа.
* Результат для следующего шага: Переход к оповещению команды.

## 7а (Отказ): Оповещение команды аналитиков
* Что происходит: Сервер инференса продолжает бесперебойно работать на предыдущей стабильной версии. Пайплайн отправляет уведомление команде аналитиков с сылкой на упавший эксперимент в MLflow для ручного разбора причин.
* Результат для следующего шага: Инцидент зафиксирован, стабильность продакшена сохранена, команда приступает к диагностике данных.
