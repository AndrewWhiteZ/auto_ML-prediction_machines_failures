# Model Card: Прогнозирование отказов оборудования (Predictive Maintenance)

**Краткое описание:** Автоматизированный ML-пайплайн для классификации отказов промышленного оборудования по риску возникновения отказа и формированию рекомендаций для их исправления

## 1. Общие сведения (Model Details)

* **Название модели:** `auto_ML-prediction_machines_failures`
* **Версия:** `v1.0.0`
* **Архитектура:** CatBoostClassifier с балансом классов для рабоы ст категориальными признаками 
* **Разработчик:** Групповой проект
* **Дата релиза:** 17 октября 2026 г.
* **Репозиторий/Артефакт:** `https://github.com/AndrewWhiteZ/auto_ML-prediction_machines_failures`

## 2. Назначение и область применения (Intended Use)

Производственное оборудование генерирует телеметрию (температура, обороты, момент, износ инструмента).
Необходимо заранее оценивать вероятность отказа (Machine failure), чтобы:

* сократить внеплановые простои;
* планировать обслуживание по риску, а не по календарю;
* выдавать рекомендации по КПД и износу инструмента.

## 3. Данные и признаки (Data)

### Обучающая выборка (Training Dataset)
* **Источник данных:** Датасет [Binary Classification of Machine Failures из Kaggle Playground Series S3E17](https://www.kaggle.com/competitions/playground-series-s3e17).
* **Размер выборки:** `~137,5` тысяч записей, `4239` записей отказов оборудования.
* **Баланс классов:** Выборка сильно несбалансирована (доля отказов ~1.8%). Применялись методы сэмплинга (SMOTE / взвешивание классов).

### Валидационная выборка (Evaluation Dataset)
* **Стратегия валидации:** Временное разделение (Time-based split). Обучение на данных до 01.2026, валидация на данных с 01.2026 по 06.2026. Это исключает заглядывание в будущее.

### Ключевые признаки (Top-5)
| Признак | Важность |
|---------|------------|
| Torque [Nm] | 11,37 |
| Air temperature [K] | 10,75 |
| Rotational speed [rpm] | 10,68 |
| air_mass | 9,97 |

### Результаты
* **Риск отказа:** вероятность отказа переведенная в значение перечисления ["Низкий", "Средний", "Высокий"] по заданным квантилям
* **Рекомендация:** в зависимости от значений признаков формирует структуру описывающую проблему, решение и приоритет
Пример:
```
{
  "Проблема": "Низкая эффективность системы",
  "Решение": "Настроить систему при КПД < 50.0%",
  "Приоритет": "Высокий",
}
```

## 4. Метрики эффективности (Metrics)

### Технические метрики
* **Основная метрика:** **Recall (Полнота)** — критически важно поймать как можно больше реальных отказов.
* **Дополнительная метрика:** **Precision (Точность)** — высокий уровень ложных срабатываний (ошибка первого рода) перегрузит ремонтную бригаду.
* **Текущие результаты:**
  * Recall: `0.85` (выявляет 85% поломок).
  * Precision: `0.72` (72% предупреждений оказываются реальными проблемами).
  * F1-Score: `0.78`

![Confusion matrix](docs/images/confusion_matrix.png)

### Бизнес-метрики (Ожидаемый эффект)
* **Предупреждение аварий:** Сокращение внеплановых простоев оборудования на `N%`.
* **Инференс:** Время инференса < `0,5 с` на один агрегат.

## 5. Ограничения и особенности (Limitations & Biases)

* **Зависимость от датчиков:** Если один из ключевых датчиков (например, датчик вибрации) выходит из строя, модель может выдавать ложные аномалии.
* **Сезонность:** Модель может работать менее точно в экстремальных погодных условиях (зима/лето), если температура окружающей среды влияет на датчики внутри цеха.

## 6. Этические соображения и безопасность (Ethical & Safety Considerations)

* **Безопасность персонала:** Ошибочный прогноз модели (пропущенный отказ) не должен приводить к угрозе жизни сотрудников. Вся критическая автоматика безопасности должна дублироваться аппаратными решениями.
